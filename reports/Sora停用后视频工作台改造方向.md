# 把 Sora2App 重建为多供应商视频渲染队列

Sora2App 应该从“Sora 2 批量外壳”改造成一个 MIT 许可、本地优先、多供应商的 **AI 视频渲染队列**。用户自带密钥，把提示词列表、CSV 或镜头表交给它，然后就可以离开：它按各家的并发上限排队，断点续跑，重试时不重复扣费，在结果链接过期前自动下载，并为每个输出留下出处记录。做出这个判断有三条依据。第一，Sora 2 / Videos API 已于 2026-09-24 停用，而且没有继任者；它背后那种 50% 折扣的服务端 Batch，在视频领域已经找不到对应物。Google、xAI、阿里、火山的批量或离线折扣都不覆盖当前旗舰视频模型，只有 Vidu 的 `off_peak` 还能打到约五折。第二，2026 年 10 月的第一梯队（Gemini Omni 1.1 Flash、Wan 3.0、Seedance 2.5、MiniMax H3）在不同榜单上互有胜负，选型实际取决于价格、可达性和并发，画质已拉不开差距。第三，开源界“可靠的官方 API 批量执行层”几乎没人做：同类批量工具都不超过 10 星，“剧本到成片”套件却已挤满数千到上万星的项目。首批接入建议如下。海外用户用 OpenRouter 统一视频接口，加上 Gemini API 的 `gemini-omni-1.1-flash`（720p 约 $0.10/秒，与 Sora 2 标准价持平）。中国大陆用户用阿里云百炼（Wan 3.0；同一把密钥还能调用可灵、Vidu、PixVerse、MiniMax H3），加上火山方舟 Seedance 2.x。本地/自托管先做 OpenAI 兼容 `/v1/videos` 适配器（SGLang Diffusion 和 vLLM-Omni 可以几乎原样复用现有的 Sora 代码），再做 ComfyUI 适配器。工程上最大的改动其实不是换 API，而是改掉“每个任务都活在一个流式 HTTP 响应里”这种结构，换成持久化任务库加按供应商限流的调度器。OpenAI 的 24 小时 Batch 没了，只有这样才能接替它。主要风险有四：模型更替极快；大陆与海外的账号和支付彼此割裂；国内个人账号只有 2–3 路并发；调研时多数一手页面无法直接打开，10 月 22 日前后的若干关键事实必须在动工前复核。

> **证据说明。** 本报告综合了五份调研笔记（2026-10-08）。研究环境的代理屏蔽了绝大多数厂商一手页面，所以多数事实来自搜索摘要和第三方博客，其中不少出自相互竞争的转售商。文中沿用笔记里的标记：**[UNVERIFIED]** 表示只有单一二手来源或未能核实，**[CONFLICT]** 表示来源互相矛盾，**[>3mo]** 表示信息早于约 2026-07-08。标为“笔者推算”的数字是基于引用数据的算术，不是厂商公布的数字。代码位置对应 Sora2App v1.0.2 的 `server.js` 和 `public/app.js`。

## Sora 停用真正带走的是五折批量价，而且至今没有任何厂商补上

Sora2App v1.0.2 的整个价值都建立在 OpenAI 一家身上。它硬编码了 `sora-2` 和 `sora-2-pro` 两个模型、4–20 秒时长和 $0.10–0.70/秒的标准价（`server.js:41-99`）。批量模式则把提示词写成 JSONL，经 Files 上传后提交到 `/v1/batches`，单批上限 50,000 条（`server.js:41-44`、`994-1090`、`1131-1200`），换取约五折的批量价 ([OpenAI Batch 指南](https://developers.openai.com/api/docs/guides/batch))；有二手来源称，Sora 2 是整个视频领域唯一公开批量折扣的地方 ([CometAPI](https://www.cometapi.com/ai-video-api-pricing/))。OpenAI 于 2026-03-24 宣布停止 Sora，04-26 关闭消费端 App，**09-24 关闭 Videos API 和全部 sora-2 别名，不提供继任模型** ([OpenAI 帮助中心](https://help.openai.com/en/articles/20001152-what-to-know-about-the-sora-discontinuation))。弃用表上“推荐替代”一栏是空的 ([Versely](https://www.versely.studio/blog/sora-openai-names-no-successor))。停用之后，`/videos` 请求返回 404，`GET /v1/models` 却仍然列出 sora-2 ([openclaw issue #158876](https://github.com/openclaw/openclaw/issues/158876))。Azure 上最后一个 `sora-2 2025-12-08` 版本将在 2026-10-15 退役，Foundry 里也没有替代的视频模型 ([Microsoft Q&A](https://learn.microsoft.com/en-us/answers/questions/5881436/azure-ai-foundry-sora-2-retirement-date-feels-too))。不过各 sora-2 版本的退役日期另有 6/2 一说 [CONFLICT]，无论哪个日期为准，Azure 都不能当退路。

Sora 只是 2026 年这波下线潮里最显眼的一个。Amazon Nova Reel 于 09-30 结束生命周期 ([Bedrock 模型卡](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-amazon-nova-reel.html))。Gemini API 上的 Veo 3.0/2.0 已在 06-30 关停，**Veo 3.1、3.1 Fast、3.1 Lite 三个预览模型也将于 10-22 关停**，官方推荐迁往 `gemini-omni-1.1-flash` ([Gemini 弃用表](https://ai.google.dev/gemini-api/docs/deprecations))。Runway 在 07-30 下架了 Gen-3 Alpha Turbo 和 Gen-4 Aleph ([Runway 更新日志](https://docs.dev.runwayml.com/api-details/api_changelog/))。LTX-2 在 08-15 下架，V1 同步端点将于 10-26 停止 ([LTX 更新日志](https://docs.ltx.io/api-changelog))。Luma 的 Dream Machine 和 Ray 2 已标记弃用 ([Luma llm-info](https://lumalabs.ai/llm-info))，可灵从 09-15 起陆续下线早期模型 ([可灵 API 更新公告](https://www.klingai.com/document-api/updates/api))。对 Sora2App 来说，这说明 OpenAI 那次不是个例：**任何一个后端都可能在半年内消失**。

真正难以弥补的是批量价。Gemini 官方 cookbook 写明“媒体生成模型目前不兼容 Batch API” ([Gemini cookbook](https://colab.research.google.com/github/google-gemini/cookbook/blob/main/quickstarts/Batch_mode.ipynb))。Vertex 上 Veo 3.1 的模型页把批量推理列为不支持 ([Agent Platform Veo 3.1](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/veo/3-1-generate))，Omni 的价格表只有一档，没有 Flex/Batch 列 ([Agent Platform 价格](https://cloud.google.com/gemini-enterprise-agent-platform/generative-ai/pricing))。xAI 的 Batch API 虽然接受视频任务，但**按标准价计费**，唯一的好处是不占每分钟配额 ([xAI 价格](https://docs.x.ai/developers/pricing))。火山方舟的 `flex` 离线档约为在线价的一半，却**明确排除 Seedance 2.0 和 2.5** ([火山 Seedance 2.5 教程](https://docs.volcengine.com/docs/ark/seedance-2-5?lang=zh))。百炼的五折 Batch 只覆盖文本和视觉理解模型，不含万相生成 ([阿里云 批量推理](https://help.aliyun.com/zh/model-studio/batch-inference))。智谱的半价 Batch 只给老旧的 CogVideoX-2 ([智谱定价](https://docs.bigmodel.cn/cn/guide/start/pricing))。现役模型里唯一接近 OpenAI Batch 语义的是 **Vidu 的 `off_peak`**：积分约减半，48 小时内完成，否则自动取消并退款；Q3 只在 `audio=true` 时可用 ([Vidu 产品定价](https://platform.vidu.cn/docs/pricing))。因此，改版后的“批量”只能是**客户端的持久化限流队列**。省钱则要靠选档：Omni 360p 约 $0.034/秒（笔者按 token 价推算），Veo 3.1 Lite $0.05/秒（10-22 后只在 Vertex 上有），Wan 3.0 480p ¥0.3/秒，MiniMax H3-Max 480p ¥0.33/秒，也就是“先用便宜档打样，再把选中的重渲”。

吞吐量也要重新设定预期。火山方舟个人账号的 Seedance 只有 3 路并发，按每条 1–5 分钟算，每小时约 36–180 条，50,000 条要跑几天到几周 ([火山 Seedance 2.5 教程](https://docs.volcengine.com/docs/ark/seedance-2-5?lang=zh))。Runway 的 Tier 1 只给 1–2 路并发、每天 50–200 条 ([Runway 用量分级](https://docs.dev.runwayml.com/usage/tiers/))。Gemini API 的 Tier 1–3 在滚动 10 分钟窗口内分别有 $10/$50/$200 的消费上限 ([Gemini 限流](https://ai.google.dev/gemini-api/docs/rate-limits))。按 10 秒 720p 的 Omni 片段约 $1.01 计算，Tier 1 每 10 分钟大约只能出 9–10 条（笔者推算，前提是这一上限也适用于 Omni 的输出 token，此点未经证实）。沿用自 OpenAI 的 50,000 条上限应当撤掉，换成“按账号等级估算完成时间”。

## 海外 API：Gemini Omni 领跑，10 月 22 日后 Veo 只剩 Vertex 一条难走的路

Google 已经用 **Gemini Omni** 取代了 Veo 产品线。官方 skill 对 `gemini-omni-1.1-flash` 的描述包括：文生视频、首帧生视频、首尾帧过渡、每轮延长最多 10 秒且总长不超过 40 秒、视频编辑，以及图片和视频参考；画幅为 16:9/9:16，分辨率有 360p、720p、1080p、4K 四档，时长 3–10 秒，自带原生音频；默认会生成多镜头，要单镜头得在提示词里写明 ([Omni SKILL.md](https://github.com/google-gemini/gemini-skills/blob/main/skills/gemini-omni-flash-api/SKILL.md))。Google 自己的 `gemini-api-dev` skill 把它列为**唯一**的现役视频模型 ([gemini-api-dev SKILL.md](https://github.com/google-gemini/gemini-skills/blob/main/skills/gemini-api-dev/SKILL.md))。第三方称稳定版 ID 于 08-27 上线，预览 ID `gemini-omni-flash-preview` 于 09-30 关停 ([Evolink](https://evolink.ai/blog/gemini-omni-api-status)) [UNVERIFIED]。价格按 token 计：视频输出每百万 token $17.50，720p 每秒折合 5,792 token ([Agent Platform 价格](https://cloud.google.com/gemini-enterprise-agent-platform/generative-ai/pricing))。笔者据此推算，**720p 约 $0.101/秒，与 Sora 2 标准价持平**；360p 约 $0.034、1080p 约 $0.152、4K 约 $0.304。推理文本 token 是否另计费尚未核实 [UNVERIFIED]。榜单上，Omni 在 09-21 的 Arena.ai 文生视频榜以 1516 分居首，样本是 48 个模型、71.9 万票 ([Arena.ai](https://arena.ai/leaderboard/text-to-video))；在 09-02 的 AA“带音频文生视频”镜像榜上也以 1238 分居首 ([benchmarklist AA 镜像](https://benchmarklist.com/benchmarks/artificial_analysis_text_to_video/))。但在 AA 新版 v2.0 榜上它只排第 8，1113 分 ([AA 文生视频榜](https://artificialanalysis.ai/video/leaderboard/text-to-video)) [CONFLICT]。

Omni 的问题出在接口形状上。所有操作都要走新的 **Interactions API**，参考图和参考视频必须先经 Files API 上传。官方示例脚本发起的是一个**阻塞式**的 `interactions.create`，默认超时 600 秒，4K 或长延长建议放宽到 900–1200 秒；结果以 Files URI 返回，还要带着密钥再下载一次 ([generate_video.py](https://github.com/google-gemini/gemini-skills/blob/main/skills/gemini-omni-flash-api/scripts/video/generate_video.py))。官方脚本的并行做法是客户端 `--concurrency 3` 的线程池，并不存在服务端批量 ([Omni SKILL.md](https://github.com/google-gemini/gemini-skills/blob/main/skills/gemini-omni-flash-api/SKILL.md))。原始 REST 路径，以及 `background=true` 加轮询能否用于 Omni 视频，都还没有核实 [UNVERIFIED]。可达性方面，中国大陆不在 Gemini API 的服务区内 ([Gemini 可用地区](https://ai.google.dev/gemini-api/docs/available-regions))。香港的情况有分歧：一份 2026 年 3 月的记录说 API 拒绝香港 IP ([10beasts](https://10beasts.net/gemini-hong-kong-api-blocked-vpn/))，另一份指南则把香港列为可用 ([transferllm](https://transferllm.com/blog/available-regions-for-google-ai-studio-and-gemini-api-full-country-list-restrictions-and-access-guide-2026/)) [CONFLICT]。在 EEA、瑞士和英国，不能上传视频来做编辑或延长 ([Omni SKILL.md](https://github.com/google-gemini/gemini-skills/blob/main/skills/gemini-omni-flash-api/SKILL.md))。条款还要求用户年满 18 岁、用于职业或商业目的，在 EEA/英/瑞只能用付费服务 ([Gemini API 附加条款](https://ai.google.dev/gemini-api/terms))。

Veo 在 10-22 之后只剩 Vertex（现已改名“Gemini Enterprise Agent Platform”）一条路。那里的 GA 模型 `veo-3.1-generate-001` 和 `veo-3.1-fast-generate-001` 仍在售，价格为 Veo 3.1 带音频 $0.40/秒、Fast $0.10/$0.12（720p/1080p）、Lite $0.05/$0.08 ([Agent Platform 价格](https://cloud.google.com/gemini-enterprise-agent-platform/generative-ai/pricing))。但 Vertex 的官方 REST 示例要求 OAuth 或服务账号令牌、GCP 项目、区域端点，结果写进用户指定的 GCS 存储桶 ([Vertex Veo 文档](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/video/generate-videos-from-text))，而且只有 us-central1 一个区域。对一个自带密钥的本地工具来说，这是明显的体验倒退。有开发者报告 Vertex express 模式的 API key 可以直接调 Veo，但这只是单一报告 ([EditForge PR #77](https://github.com/tdveal74-cell/EditForge/pull/77)) [UNVERIFIED]。GA 版的退役日期也有两种说法，一说“2026-11-17 或之后”，一说未列出 [CONFLICT]。

其余几家里，**xAI `grok-imagine-video-1.5`** 已正式 GA，原生 1080p，音频不另收费，480p/720p/1080p 分别为 $0.08/$0.14/$0.25 每秒 ([xAI 价格](https://docs.x.ai/developers/pricing))。它的接口和 OpenAI `/videos` 最接近：`POST /v1/videos/generations` 拿到 `request_id`，再轮询 `GET /v1/videos/{id}` ([xAI 视频文档](https://docs.x.ai/developers/model-capabilities/video/generation))。**Runway `gen4.5`** 为 $0.12/秒，720p、最长 10 秒，没有原生音频 ([Runway 价格](https://docs.dev.runwayml.com/guides/pricing/))；超限任务会被标为 `THROTTLED` 在服务端排队，分级从 Tier 1 的 1–2 路并发到 Tier 5 的 20 路 ([Runway 用量分级](https://docs.dev.runwayml.com/usage/tiers/))。**Luma Ray 3.2** 走新的 Agents API，720p 5 秒 $0.30，文档注明 GA 前价格可能调整，原生音频未获证实 ([Luma 价格](https://docs.agents.lumalabs.ai/guides/pricing/))。**BFL FLUX 3 Video** 于 08-04 开放，支持 5–20 秒并带原生音频，720p 为 $0.17/秒，草稿档 $0.06/秒 ([BFL 价格](https://docs.bfl.ml/quick_start/pricing))；有第三方称其结果 URL 约 10 分钟失效 [UNVERIFIED]。**LTX** 是最便宜的托管选项：LTX-2.3 Fast 720p $0.03/秒，LTX-2.5 Fast $0.09/秒 ([LTX 价格](https://docs.ltx.io/pricing))。Pika 2.5 的 $0.04/秒只见于第三方 ([pikaais](https://pikaais.com/api/)) [UNVERIFIED]。可以直接排除的有：Adobe Firefly，只对企业合同开放 ([Firefly API](https://developer.adobe.com/firefly-services/docs/firefly-api/api/))；Midjourney，没有官方 API，非官方封装会导致封号 ([Wireflow](https://www.wireflow.ai/blog/best-midjourney-api-tools-in-2026))；Moonvalley，API 状态说法矛盾 [CONFLICT]；Nova Reel，已经停服。

## 国内 API：价格与海外同档或更低，但个人账号只有 2–3 路并发

2026 年 10 月国内的主力阵容如下：字节 Seedance 2.5/2.0（火山方舟，国际版 BytePlus），阿里 Wan 3.0 与 HappyHorse 1.1（百炼），MiniMax H3，可灵 3.0（4.0 于 09-28 内测，开发者站仍写着“API Coming Soon”），生数 Vidu Q3，以及爱诗 PixVerse V6 ([虎嗅](https://www.huxiu.com/moment/1284349.html)；[WaveSpeed](https://wavespeed.ai/blog/ai-news/kling-4-0-release-date/))。文生视频和首帧图生视频是 Sora2App 现有的两项功能，这几家全都覆盖。它们的差别在首尾帧和多参考上：Seedance 2.5 单次 4–30 秒，最多接受 30 张图、10 段视频、10 段音频 ([火山 Seedance 2.5 教程](https://docs.volcengine.com/docs/ark/seedance-2-5?lang=zh))；最高分辨率在官方模型列表上写的是 1080p ([火山 模型列表](https://www.volcengine.com/docs/82379/1593703))，活动页 FAQ 却写 720p ([火山活动页](https://www.volcengine.com/activity/seedance25)) [CONFLICT]。Wan 3.0 单次 2–30 秒，有 480p/720p/1080p 三档，仍处于 preview 阶段，需要申请开通 ([阿里云 Wan3.0 API](https://help.aliyun.com/en/model-studio/wan3-video-generation-api-reference))；它能否自己生成音轨，文档没有说清 [UNVERIFIED]。

榜单上，国内模型占了大多数头部位置，但排名每月都在变。AA v2.0 文生视频榜上，Wan 3.0 以 1156 分排第一，Seedance 2.5 以 1143 分第三，MiniMax H3 以 1137 分第四，前两名的置信区间互相重叠 ([AA 文生视频榜](https://artificialanalysis.ai/video/leaderboard/text-to-video))。09-18 的 SuperCLUE 中文竞技场上，Seedance 2.5 以 1297.3 分居首，但只有 311 场对战，置信区间约 ±90；Seedance 2.0 1261.6 分，可灵 3.0 1193.4 分 ([SuperCLUE](https://superclueai.com/arena?tab=board&type=video))。可灵 3.0 和 Vidu Q3 在 AA 图生视频榜上排在第 18–20 名左右 ([AA 图生视频榜](https://artificialanalysis.ai/video/leaderboard/image-to-video))。

接口本身对零依赖 Node 很友好。所有厂商都是“异步创建 → 轮询 → 限时 URL 下载”这一套，和 Sora2App 现有流程一致。认证几乎都只需一个静态请求头：火山方舟、百炼、MiniMax 用 Bearer；可灵自 2026-06-17 起新接口只支持 API Key ([可灵 API 更新公告](https://www.klingai.com/document-api/updates/api))；Vidu 用 `Token`，PixVerse 用 `API-KEY`。回调要求公网 HTTPS，对绑定 127.0.0.1 的应用没有用处，只能轮询。结果链接的寿命差别很大：Seedance 和百炼都是 24 小时，百炼过期后任务状态变为 `UNKNOWN` ([阿里云 文生视频指南](https://www.alibabacloud.com/help/en/model-studio/text-to-video-guide))；经百炼转售的可灵是 30 天 ([阿里云 可灵 API](https://help.aliyun.com/en/model-studio/kling-video-generation-api-reference/))；MiniMax 有 9 小时 ([MiniMax 公告](https://www.minimax.io/news/video-generation-api)) [>3mo] 和约 24 小时两种说法 [CONFLICT]。所以**应用关闭超过一天，已完成的结果就会丢失**，必须把任务 ID 落盘并在重启后补拉。账号层面，每家都把国内站和国际站分开（火山/BytePlus、阿里云中国站/国际站、minimaxi.com/minimax.io、vidu.cn/vidu.com、拍我AI/pixverse.ai、可灵国内/全球），两边的密钥不能互用 ([阿里云 地域](https://help.aliyun.com/zh/model-studio/regions))。国内站要求实名认证和支付宝/微信付款，开通 Seedance 还需账户余额不低于 ¥200 ([火山 开通管理](https://www.volcengine.com/docs/82379/1159200))。BytePlus 的 Seedance 不对美国开放 ([The Decoder](https://the-decoder.com/bytedance-rolls-out-seedance-2-0-to-100-countries-but-keeps-the-us-off-the-list/)) [>3mo]，另有来源说加拿大、英国、澳大利亚、新西兰也不在服务范围内 ([CellCog](https://cellcog.ai/blog/seedance-2-5-pricing/)) [CONFLICT]。因此 UI 必须把“供应商 + 区域”当成一个选项来处理。

合规上，《人工智能生成合成内容标识办法》自 2025-09-01 起施行，要求视频同时带显式标识和写在元数据里的隐式标识，并禁止去除标识或提供去除工具 ([网信办通知](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm))。Seedance、Wan 3.0 和 MiniMax 的 API 默认都**不加**可见水印 ([火山 创建任务](https://docs.volcengine.com/docs/ark/create-video-generation-task-api)；[MiniMax 创建任务](https://platform.minimax.io/docs/api-reference/video-generation-v2-create))，标识义务实际上落到了发布者身上。Seedance 2.x 拒收含真实人脸的直接上传，要先在控制台完成人脸核验和肖像授权 ([火山 创建任务](https://www.volcengine.com/docs/82379/1520757))。对批量工具来说，这意味着审核失败必须按单条任务上报，不能拖垮整批。

## 聚合平台：OpenRouter 的统一接口几乎就是 Sora 代码的替身

在主要聚合平台里，OpenRouter 是唯一有真正统一视频接口的一家。它在 2026-04-15 上线视频生成 ([OpenRouter 公告](https://openrouter.ai/blog/announcements/video-generation/))，到 10 月已覆盖 Veo 3.1（标准/Fast/Lite）、Seedance 2.0/2.5、可灵 v3/O1、Wan 2.6/2.7/3.0、海螺、Grok Imagine 和 HeyGen ([OpenRouter 图生视频对比](https://openrouter.ai/blog/insights/image-to-video-models-compared/)；[选模型指南](https://openrouter.ai/docs/cookbook/video-generation/choose-video-model))。按近 7 天生成秒数排名，前三是 HeyGen Video、Seedance 2.5 和 Veo 3.1 Lite ([OpenRouter 视频合集](https://openrouter.ai/collections/video-models))。流程是 `POST /api/v1/videos` 建任务、轮询状态，再从 `/api/v1/videos/{jobId}/content` 下载 ([OpenRouter 视频文档](https://openrouter.ai/docs/guides/overview/multimodal/video-generation))，**结构上和 Sora2App 现有的 create → poll → download 一一对应**。首帧参考图对应 `frame_images[{frame_type:"first_frame"}]`。更有价值的是 `GET /api/v1/videos/models`：它按模型返回 `supported_durations`、`supported_resolutions`、`supported_aspect_ratios`、`supported_frame_images`、`generate_audio`、`pricing_skus` 和可透传参数 ([OpenRouter 模型列表 API](https://openrouter.ai/docs/api/api-reference/video-generation/list-all-video-generation-models))，正好可以驱动一个通用表单，新模型上线不用改代码。OpenRouter 声称不加价 ([OpenRouter FAQ](https://openrouter.ai/docs/faq))，收入来自约 5.5% 的充值手续费 ([Amnic](https://amnic.com/blogs/openrouter-pricing))；支持信用卡、支付宝和 USDC ([OpenRouter 支持](https://openrouter.ai/support))，但从中国大陆访问一般需要代理 ([yangmao.ai](https://yangmao.ai/en/providers/openrouter/china-access/))。还有几点尚未核实 [UNVERIFIED]：字段名是否与 OpenAI 一致（`seconds` 还是 `duration`）、视频输出的保留期和并发上限、Sora 条目是否已下架，以及 **Veo 3.1 Lite 在 10-22 之后是否继续供应**。

fal 和 Replicate 的模型目录最全，但每个模型的输入 schema 各不相同。fal 新账号起步只有 2 路并发，随充值自动升到 40 路，超限请求排队而不是被拒；媒体文件在 CDN 上至少保留 7 天，可以用 `X-Fal-Store-IO: 0` 请求头不让平台保存请求 JSON ([fal FAQ](https://fal.ai/docs/model-apis/faq)；[fal 媒体过期](https://fal.ai/docs/documentation/model-apis/media-expiration))。Replicate 已被 Cloudflare 收购，API 输出默认约 **1 小时后清除** ([Replicate 数据保留](https://replicate.com/docs/topics/predictions/data-retention.md))，可灵 3.0 Pro 的标价约为直连的 2 倍 ([teamday](https://www.teamday.ai/blog/ai-api-pricing-comparison-2026))。fal 上 Seedance 2.0 720p 标价 $0.3034/秒 ([Infer](https://tryinfer.com/pricing/seedance-2-0-pro))，约为 BytePlus 直连价的 2 倍。可见**没有哪家聚合平台在所有模型上都最便宜**。三大云市场则基本派不上用场：Azure 已没有视频模型，Bedrock 只有 Luma Ray 2，Vertex 只卖 Google 自家的模型 ([AWS Luma 文档](https://docs.aws.amazon.com/bedrock/latest/userguide/model-parameters-luma.html))。对中文用户，WaveSpeedAI 支持支付宝、微信和 Naver Pay，在支付上最友好 ([WaveSpeed 支付方式](https://wavespeed.ai/docs/payment-methods))，但新账号只有 2 路并发、每分钟 5 次。

低于官方价的转售商和中转站，风险已有记录。Kie.ai 主页宣传 Veo 3.1 比官方便宜约 60–73% ([Kie.ai](https://kie.ai/))，评测记录了任务卡住、积分“消失”和 Trustpilot 2.5 分 ([aireiter](https://aireiter.com/blog/kie-ai-review-2026))。二手报道称，一项 2026 年 3 月对 17 家中转站的审计发现，多数没有可核验的主体身份，还会悄悄切换上游；同一模型经中转后医疗问答准确率从 83.82% 跌到约 37% ([知乎](https://zhuanlan.zhihu.com/p/2032951488624977427))。2026 年 4 月的整治关停了数百家中转站 ([知乎](https://zhuanlan.zhihu.com/p/2053108165076575812))。这两条报道的具体出处都未能逐一核实 [UNVERIFIED]。所以中转站不宜做默认选项，只应作为“自定义端点”供高级用户自担风险使用。这类端点可以兼容 OpenAI `/v1/videos`，也可以兼容中转常用的 new-api `POST /v1/video/generations`（通用字段加 `metadata`）([new-api 文档](https://docs.newapi.pro/api/generate-video))，并配上明确的风险提示。

## 开源本地：能跑但不是平替，Mac 只适合当遥控器

开源权重的格局在 2026 年 8 月变了。**MiniMax H3**（33B）可以生成 15 秒 2K 视频，带立体声，支持首尾帧和多参考，在 AA v2.0 文生视频榜上排总榜第 4（1137 分），是最强的开源模型 ([AA 开源文生视频榜](https://artificialanalysis.ai/video/leaderboard/text-to-video/open-weights))。但它的社区许可**排除美国、欧盟、英国和韩国**，年营收约 2,000 万美元以上的机构还需另行授权 ([explainx](https://explainx.ai/blog/minimax-h3-open-video-model-hailuo-july-2026)) [UNVERIFIED，二手]。**LTX-2.5**（22B，08-11 发布）带原生音频，年经常性收入 1,000 万美元以下的机构可免费使用，但输出必须标注为机器生成 ([VentureBeat](https://venturebeat.com/technology/ltx-2-5-can-generate-a-10-second-ai-video-from-an-image-in-just-6-8-seconds-on-nvidia-superchips-and-its-open-weights))；它在 AA 上只有约 946 分。**Wan 2.2** 是唯一许可完全宽松（Apache-2.0）的一线模型，但已经是 2025 年 7 月的产物。阿里此后连续四代旗舰（2.5、2.6、2.7、3.0）都没有开源权重 ([Atlas Cloud](https://www.atlascloud.ai/blog/tips/is-wan-3.0-open-source))。从 Sora 2 迁到宽松许可的本地模型，用户要接受大约 200 Elo 的画质差距。

硬件门槛把本地生成限定在 NVIDIA 上。用 RTX 4090/5090 加蒸馏 LoRA，Wan 2.2 14B 生成 5 秒 720p 约需 1 分 45 秒到 5 分钟 ([bestgpuforai](https://bestgpuforai.com/articles/rtx-5090-vs-4090-for-video-gen/))，默认步数下约 9 分钟 ([MindStudio](https://www.mindstudio.ai/blog/what-is-wan-2-2-video-open-source))。H3 在 5090 上生成 10 秒 480p 约 175 秒，15 秒 1344×768 约 518 秒 ([ai-muninn](https://ai-muninn.com/en/blog/minimax-h3-rtx5090-config-stack))。这样一块 GPU 每小时只能出 20–30 条，50,000 条需要 1,700–2,500 GPU 小时（笔记推算）。Mac 上则很难用：Metal 不支持 FP8，M1 Max 跑 GGUF 版 Wan 2.2，2 秒片段要 82 分钟 ([lilting.ch](https://lilting.ch/en/articles/ltx2-wan22-mac-local-video-gen))；只有 LTX-2.x 的社区 MLX 移植算勉强可用，在 128GB 的 M4 Max 上约 206 秒 ([LTX-2.3 MLX](https://huggingface.co/gajesh/LTX-2.3-mlx-fp16))。Sora2App 以 macOS 安装包分发，所以它的合理形态是**在 Mac 上当队列前端，算力放在局域网 PC 或云端 GPU 实例上**。

集成上有个难得的巧合：**本地推理服务器正在实现 OpenAI Videos API 本身**。SGLang Diffusion 在 `/v1/videos` 下实现了 OpenAI Videos API 的一个子集，官方 OpenAI 客户端改个 base URL 就能 `videos.create`、轮询和下载 MP4，图生视频支持 multipart 上传 ([SGLang 文档](https://docs.sglang.io/docs/sglang-diffusion/api/openai_api))。vLLM-Omni 提供异步的 `/v1/videos` 和同步的 `/v1/videos/sync` ([vLLM-Omni 文档](https://docs.vllm.ai/projects/vllm-omni/en/latest/serving/videos_api/))，还为 H3 准备了 4090/5090 的部署配方 ([vLLM 配方](https://recipes.vllm.ai/MiniMaxAI/MiniMax-H3))。这意味着 `createVideo`、`retrieveVideo`、`downloadVideo`（`server.js:843-990`）只要把写死的 `https://api.openai.com/v1/videos` 改成可配置，就能直接驱动 Linux/NVIDIA 上的本地模型。ComfyUI 覆盖的模型最广，H3 和 LTX-2.5 都是首日支持，接口是 `POST /prompt` → `/ws` 或 `/history/{id}` → `/view` ([ComfyUI 服务端路由](https://docs.comfy.org/development/comfyui-server/comms_routes))。但它**默认没有任何鉴权** ([Runflow](https://www.runflow.io/blog/comfyui-api-endpoints))，默认端口是 8188 还是 8000 也说法不一 [CONFLICT]。远程使用时应走 SSH 隧道。

成本上，本地最划算的方式是租实例，而不是自购硬件。AutoDL 上 4090 约 ¥1.88/小时、5090 约 ¥2.78/小时，按秒计费 ([AutoDL](https://www.autodl.com/))；Vast.ai 上 5090 约 $0.27–0.43/小时 ([getdeploying](https://getdeploying.com/gpus/nvidia-rtx-5090))。折算下来每条 5 秒 720p 约 $0.01–0.10，而 RunPod 托管 Wan 2.2 是每条 $0.30 ([RunPod 价格](https://www.runpod.io/pricing))，相差 3–30 倍。这个优势只有在**队列能连续把实例跑满**时才成立，而这恰好是渲染队列的本职工作。

## 竞品与需求：短剧套件已挤满数千至上万星项目，批量执行层却无人认领

开源竞品已经分成了两极。一极是重型的“剧本 → 分镜 → 成片”智能体套件，大多面向国内短剧和漫剧，且多在 2026 年 1–3 月创建。waoowaoo 有 14,380 星，通过 OpenRouter 自带密钥，技术栈包括 Docker、MySQL、Temporal 和 Redis；它从 v0.5.0-beta.1 起改用 Elastic License 2.0，自称“非 OSI 开源” ([waoowaoo](https://github.com/waooAI/waoowaoo))。dramaclaw 有 6,708 星，Jellyfish 有 6,620 星，ArcReel 有 5,343 星（AGPL 许可，能在生成前后显示费用）([ArcReel](https://github.com/ArcReel/ArcReel))。另一极是单次生成的多模型工作台：Nomi 有 550 星，主打本地优先和自带密钥，带 24 个工具的 MCP 服务器，采用 AGPL，但没有批量功能 ([Nomi](https://github.com/aqm857886159/Nomi))；Open-Generative-AI 有 29,811 星，采用 MIT，但云端生成绑定 Muapi 密钥 ([Open-Generative-AI](https://github.com/Anil-matcha/Open-Generative-AI))。夹在两极之间的批量工具都很小。Sora2App 自己是 0 星 ([videogen](https://github.com/swf-cmd/videogen))。09-30 新出的 PowerTokens/video-studio 只有 1 星，它支持从 Excel/CSV 批量跑 Wan 3.0，宣传“续跑不重复扣费”，但绑定自家 API ([PowerTokens](https://github.com/PowerTokens/video-studio))。G-Labs-Studio 有 9 星，靠消费者账号而不是 API 密钥运行 ([G-Labs-Studio](https://github.com/duckmartians/G-Labs-Studio))。即梦方向的批量工具则依赖 sessionid 或 cookie ([seedance2.0.1](https://github.com/zero199901/seedance2.0.1))。主流的自带密钥聊天客户端基本不做视频，LobeHub 是例外 ([LobeHub v2.1.41](https://newreleases.io/project/github/lobehub/lobehub/release/v2.1.41))。Sora 专用项目的下场很说明问题：sora2api（1,235 星）和 SoraWatermarkCleaner（1,146 星）都已归档 ([sora2api](https://github.com/TheSmallHanCat/sora2api))，还在更新的是早已支持多供应商的 AI-video-Replicate ([AI-video-Replicate](https://github.com/xiaohuihui202504/AI-video-Replicate))。

需求端最大的一块是国内的 AI 短剧和漫剧。DataEye 数据显示，2026 年上半年抖音新上线 22.19 万部 AI 原生短剧和漫剧，累计播放 5,157 亿次，但播放破亿的只有 1,055 部 ([知乎](https://zhuanlan.zhihu.com/p/2070176014383296993))。爆款率约 1%，中腰部公司只有 3–5% 盈利 ([掘金](https://juejin.cn/post/7692065346283110440))。广电总局的 AI 漫剧“先备案后上线”自 2026-04-01 起强制执行，“生产过程留痕”成了硬要求 ([21财经](https://www.sfccn.com/2026/4-10/yMMDE0NDlfMjEyODAyMg.html))。会员制也在收紧：即梦三档年费会员（659/1,899/5,199 元）的月积分从 1080/4000/15000 砍到 725/2210/6160 ([蓝鲸财经](https://www.lanjinger.com/d/1775803661543374566))，澎湃对顶档给出的数字不同 [CONFLICT]；有创作者测算，一条 2 分钟视频的成本从 5.2 元涨到 40.2 元 ([澎湃](https://m.thepaper.cn/newsDetail_forward_32940440))。第二块是投放和电商：63%（Wyzowl）到 86%（IAB）的营销人员或广告买家在用或打算用 AI 做视频 ([adwave](https://adwave.com/resources/ai-video-statistics-2026))。但 36% 的消费者认为 AI 视频会降低品牌信任 ([Animoto/BusinessWire](https://www.businesswire.com/news/home/20260121875037/en/83-of-Consumers-Can-Spot-AI-Videos-36-Say-It-Lowers-Brand-Trust-According-to-Animotos-New-Report)) [>3mo]。商业平台把批量做成了画布节点，比如 Freepik Lists、Figma Weave 迭代器和 Flora Batch，按积分计费 ([Magnific](https://www.magnific.com/blog/spaces-generate-whole-set-visuals-one-shot/))。零售加价相当可观：一条 15 秒的 Seedance 2.5 在 Higgsfield 或 OpenArt 上约 $4.2–4.4 ([Kolbo](https://kolbo.ai/blog/seedance-2-5-pricing))。第三块是智能体和自动化开发者：drama-skills（2,580 星）和 seedance2-skill（4,222 星）只负责生成提示词，本身不负责执行 ([drama-skills](https://github.com/zenstory-ai/drama-skills))。

这些人群反复提到的痛点几乎都在“执行层”。视频任务长时间占用 GPU，所以并发上限比 RPM 先卡住，Veo 的批量作业得先申请提额 ([Atlas Cloud](https://www.atlascloud.ai/blog/guides/debugging-ai-video-common-api-errors-and-how-to-optimize-your-rendering-pipeline))。被 429 拒绝的创建请求不会自动排队，结果链接大约 24 小时过期，各模型的字段名也各不相同 ([bitdoze](https://www.bitdoze.com/kie-ai-video-generation/))。有人提醒，可灵 API 的参数“今天硬编码，一个月后就落后一个版本” ([kling-api.github.io](https://kling-api.github.io/))。PowerTokens 把“续跑不重复扣费”写进卖点，说明重复扣费是真实的顾虑。V2EX 上甚至有人推荐养号加多账号轮换来省积分 ([V2EX](https://www.v2ex.com/t/1193030))。这说明国内用户对批量吞吐的需求大到愿意冒违反服务条款的风险。不过，手里握有 API 密钥的用户仍是少数，大众市场主要靠会员和 cookie 工具。

## 改造方向：做 AI 视频的“渲染队列”，并按用户所在地分配首批适配器

### 定位：MIT、本地、多供应商，为“交给它就走开”而设计

推荐的定位是：**一个 MIT 许可、本地运行、多供应商的 AI 视频渲染队列**。用户自带密钥，输入列表、CSV 或镜头表；工具遵守限流，重试不重复扣费，自动下载全部结果并记录出处；界面有中、日、英、韩四种语言，也可以由编码智能体调用。这个定位直接继承了 Sora2App 现有的优势：零依赖 Node、只绑定 127.0.0.1、密钥不落盘、空行切分提示词、自动轮询下载、首帧图、四语界面和 macOS 安装包。补上的正是竞品普遍缺失的部分：多供应商适配器、调度器、断点续跑、成本预估和出处记录。四语界面能否成为差异点只是推断，因为调研中看到的竞品 README 只有中英文。三件事应明确列为**不做**：写剧本、时间线剪辑、无限画布，这些已有 Nomi、ArcReel、waoowaoo 和各家画布产品覆盖。去水印和 cookie/sessionid 方案既违反服务条款，也违反国内的标识规定，同样不做。产品名里的“Sora”指向一个已停用的产品，建议改名，直接沿用仓库名 videogen 即可。

### 优先级：先修任务持久化，再扩供应商

排序的原则是：先解决“关掉标签页就丢掉付费任务”这个结构缺陷，再加供应商。原因在于，以前 OpenAI 的服务端 Batch 替用户托管了 24 小时的排队，现在这段排队全部转移到了用户本机。

| 优先级 | 改动 | 理由 |
|---|---|---|
| P0 | 持久化任务库 + 可恢复调度器（按供应商和区域分别设并发信号量，处理 429/THROTTLED 退避，创建成功立即落盘任务 ID，重启后补轮询并下载） | 替代 24 小时 Batch 的唯一办法；百炼和方舟的结果 24 小时过期，Replicate 约 1 小时 |
| P0 | Provider 适配器接口（`capabilities / create / poll / download / uploadAsset`）+ 带 as-of 日期、用户可编辑的模型与价格数据文件 | 模型 ID 一年换几轮，促销期只有 2–8 周 |
| P0 | “OpenAI 兼容 Videos”适配器（base URL 和模型可配置） | 改动最小，可立刻驱动 SGLang Diffusion、vLLM-Omni 和部分中转 |
| P1 | OpenRouter、Gemini Omni、百炼（北京/新加坡）、火山方舟/BytePlus 四个适配器；“供应商 + 区域”选择；代理设置；提交前成本预估 | 覆盖海外与大陆两类用户的首选路径 |
| P2 | CSV/XLSX 和变量矩阵输入；每条 N 个 take 加审片网格；首尾帧与参考图；出处 manifest；ComfyUI 适配器；MiniMax、Vidu 错峰、xAI、fal | 服务短剧镜头表和电商变体矩阵两类批量需求 |
| P3 | CLI 与 MCP；多后端扇出；可选的“AI 生成”可见标识；Windows/Linux 打包；可灵 4.0 等新模型 | 把工具变成智能体和 skills 生态的执行层 |

### 首选接入：海外走 OpenRouter + Gemini，大陆走百炼 + 火山方舟

海外用户（日、韩、欧、美）的第一个适配器应当是 **OpenRouter**。它和现有代码最接近，一把密钥就能用到第一梯队的大多数模型，还能用 `/videos/models` 自动生成表单。第二个是 **Gemini API `gemini-omni-1.1-flash` 直连**：Arena.ai 和 AA 带音频榜把它排在第一（AA v2.0 榜例外），720p 价格与 Sora 2 标准价持平，又有 360p 草稿档，代价是 Interactions API 的阻塞式调用和 Files 上传。之后可选的是 xAI（接口最像 OpenAI）、fal（作为第二个聚合平台，对冲对 OpenRouter 的依赖）、Runway 和 LTX。

中国大陆用户的第一个适配器应当是**阿里云百炼（北京）**。Wan 3.0 在 AA 上排第一，720p 只要 ¥0.6/秒；接口是 Bearer 密钥加 `X-DashScope-Async: enable` 的异步任务；同一把密钥还能调用经百炼转售的可灵、Vidu、PixVerse 和 MiniMax H3 ([阿里云 MiniMax H3](https://help.aliyun.com/zh/model-studio/minimax-video-generation-api-reference))，可以说“一个适配器，多个模型”（转售模型的参数与价格是否与直连一致，尚未逐一核实）。再接新加坡区，就能顺带服务海外用户。第二个是**火山方舟 Seedance 2.x**，它在中文用户偏好榜上居首，多参考能力最强，但价格最高、个人账号只有 3 路并发。之后可选的有 MiniMax 直连（便宜，30 个在途任务）、Vidu 直连（`off_peak` 是唯一约五折的批量模式）和 AutoDL 加 ComfyUI。

| 用户群 | 首选 | 第二 | 可选补充 | 暂不建议 |
|---|---|---|---|---|
| 海外（日 / 韩 / 欧 / 美） | OpenRouter `/api/v1/videos` | Gemini API `gemini-omni-1.1-flash` | xAI Grok 1.5、fal、Runway、LTX；百炼新加坡、minimax.io、vidu.com | Vertex Veo（OAuth+GCS）、Adobe、Midjourney、Kie 与匿名中转 |
| 中国大陆 | 阿里云百炼（北京）：Wan 3.0 + 转售可灵/Vidu/PixVerse/H3 | 火山方舟 Seedance 2.0 / 2.5 | MiniMax 直连、Vidu `off_peak`、AutoDL + ComfyUI | 依赖代理直连海外 API；cookie/sessionid 工具；未审计中转 |
| 本地 / 自托管 | OpenAI 兼容 `/v1/videos`（SGLang Diffusion、vLLM-Omni） | ComfyUI（Wan 2.2、LTX-2.5 模板；H3 附许可提示） | Mac 上 LTX MLX（64GB 以上，实验性） | 在 Mac 本机跑 Wan 或 Hunyuan |

可灵 3.0 价格适中，国内外同价，也已改为 API Key 认证，却没有排进首批。原因是 4.0 的 API 预计在 10 月内开放，现在写的适配器可能几周后就得重写；而在过渡期，用户可以经百炼或 OpenRouter 用到可灵 3.0。

## 架构改动：约 780 行 OpenAI 专用代码要换，任务库成为新的核心

按函数边界统计，OpenAI 专用代码和任务编排加起来大约 780 行，接近 `server.js`（1,722 行）的一半：常量在 `server.js:41-99`，请求与视频生命周期在 `843-990`，Files 与 Batch 在 `994-1090` 和 `1131-1200`，`handleGenerate*`、`handleStatus`、`handleDownload` 等处理函数在 `1215-1620`。好在可复用的部分恰好是最难写的那些。`withIdempotentRetry` 只对幂等操作（查询、下载）针对 408、429、5xx 和网络错误做指数退避，并尊重 `Retry-After`（`server.js:873-915`），而 `createVideo` 本身不在重试范围内。这正是“不重复扣费”的底层基础。PNG、JPEG、WebP 的首帧尺寸解析（`server.js:489-625`）、前端把图片画布适配到目标分辨率（`public/app.js` 约 939-1070）、四语 i18n、输出路径安全（不覆盖、文件名清洗）、空行切分和数量控制，都可以原样保留。

| 模块 | 现状 | 改造 | 工作量 |
|---|---|---|---|
| 模型、尺寸、时长、价格常量 | `server.js:41-99` 硬编码 sora-2 / sora-2-pro | 迁入按“供应商 × 区域”组织、带 as-of 日期的数据文件；能从 OpenRouter `/videos/models` 刷新 | 小 |
| 请求与视频生命周期 | `server.js:843-990`，base URL 写死为 api.openai.com | 改造成第一个适配器“OpenAI 兼容 Videos” | 小 |
| Files 上传、`/v1/batches`、JSONL 解析 | `server.js:994-1090`、`1131-1200` | 删除，由本地队列取代 | 删除 |
| 任务编排 | `handleGenerateStream`（`server.js:1261` 起）、`handleGenerateBatchStream`（`server.js:1335-1582`），任务生命周期绑在一个 NDJSON 流式响应上 | 拆成任务库、调度器和可重连的事件流 | 大 |
| 重试 | `server.js:873-915` 只重试幂等操作 | 保留；扩展为按供应商退避，并识别 THROTTLED 和业务错误码 | 小 |
| 首帧图像 | `server.js:489-625`；`public/app.js` 约 939-1070 | 保留；新增上传或资产步骤（Gemini Files API、ComfyUI 上传、base64） | 中 |
| 目录选择器 | 仅 macOS 的 `osascript`（`server.js:820` 附近） | 非 macOS 时改为手动输入路径 | 小 |

新的结构可以概括为一句话：**浏览器只是观察者，队列跟着服务进程走**。服务端提供 `POST /api/jobs` 入队、`GET /api/jobs` 查询，以及一个可断线重连的事件流。每次状态变化都以追加方式写入本地 NDJSON 任务库，路径可以是输出目录下的隐藏目录或用户数据目录。每条记录包含供应商、区域、base URL、模型、参数、提示词、首帧哈希、远端任务 ID、状态、成本估算、输出路径和时间戳，**但不包含密钥**。这就带来一个和隐私原则直接冲突的问题：密钥不落盘，重启后队列就无法自动继续。合理的解法是重启后显示“N 个进行中任务等待重新输入某供应商密钥以继续”；系统钥匙串可以留作日后的显式可选项。防止重复扣费分三层。第一，创建请求返回后立即落盘任务 ID。第二，凡供应商支持幂等键的，都用本地生成的任务 UUID 作为幂等键，例如 PixVerse 的 `Ai-trace-id`（重复使用不会生成新视频）和可灵的 `external_task_id`（账号内唯一）([PixVerse 文生视频](https://docs.platform.pixverse.ai/text-to-video-generation-13016634e0)；[可灵文生视频参考](https://kling.ai/document-api/apiReference/model/textToVideo))。第三，创建结果不明时，把任务标成“需人工确认”，绝不自动重发。调度器按“供应商 + 区域 + 账号”分别持有并发信号量，默认值取自数据文件（例如方舟个人账号 3、MiniMax 30、fal 2），用户可以调高。结果一到就立即下载，因为 BFL 的链接可能只有约 10 分钟，Replicate 约 1 小时。Omni 的阻塞式调用在调度器里视为“占用一个并发槽的长请求”。ComfyUI 需要用到 WebSocket；笔记指出，内置 WebSocket 要 Node 22 以上，而 Node 22.21 以上的 `fetch` 还要设置 `NODE_USE_ENV_PROXY=1` 才会走代理。因此，嵌入的运行时应从当前的 Node 18 基线升级，这两点在实施时也要复核。现有的 Host/Origin 校验和路径脱敏继续保留；ComfyUI 默认绑定 127.0.0.1，远程使用一律走 SSH 隧道。P0 的任务库分两步落地：阶段 0 先做追加式任务日志，保证付费任务至少能人工找回；阶段 1 再补上完整的调度和自动续跑。

| 阶段 | 时间窗（自 2026-10-08 起） | 交付 | 退出标准 |
|---|---|---|---|
| 0 止血（v1.1） | 10/08–10/24 | UI 和 README 标明 Sora 已停用；常量迁入数据文件；适配器接口雏形，完成“OpenAI 兼容 Videos”和 OpenRouter 两个适配器；创建成功即追加写任务日志；README 写明各家地区和条款限制 | 不改交互即可用 OpenRouter 和本地 SGLang/vLLM-Omni 生成并下载 |
| 1 渲染队列（v2.0） | 10 月底–12 月初 | 任务库、调度器、断点续跑；“供应商 + 区域”选择与代理；成本预估；Gemini Omni、百炼、火山方舟/BytePlus 适配器；升级嵌入的 Node | 100 条任务跑到一半时关闭标签页并重启服务：0 丢失，0 重复创建 |
| 2 批量生产（v2.x） | 12 月–2027 年 1 月 | CSV/XLSX 和变量矩阵；N 个 take 加审片网格；首尾帧与参考图；出处 manifest；ComfyUI 适配器；MiniMax、Vidu 错峰、xAI、fal | 一份“SKU × 场景 × 画幅”矩阵可以一键展开、审片，并按规则命名导出 |
| 3 生态（v3） | 2027 年一季度 | CLI 与 MCP；多后端扇出；可选的可见“AI 生成”标识；Windows/Linux 打包；可灵 4.0 等新模型 | 智能体可以通过 MCP 提交、查询和下载；多个 GPU 后端并行 |

## 主要风险与动工前必须复核的事实

最大的风险是**模型更替的速度超过一个人的维护速度**。仅 2026 年，Google 的视频模型 ID 就换了三轮（Gemini API 上的 Veo 3.x 先后退场，Omni 又从预览 ID 换到 1.1 稳定 ID）；国内模型 ID 带日期后缀（如 `-260628`），排行榜榜首几乎每月易主。缓解办法是把能力和价格都放进数据文件，弃用时在 UI 里提前告警，并提供“把这批任务改投到另一个模型”的一键操作；同时把适配器控制在两家聚合平台加两三家直连。第二个风险是**可达性和支付割裂**：没有任何西方 API 正式服务中国大陆，国内各家的国际站和国内站密钥不能互用，BytePlus 不对美国开放，Gemini 的条款要求 18 岁以上并用于商业目的。工具没法“修好”这些，只能把它们写清楚。第三个风险是**成本卖点变弱**：没有了五折批量价，卖点只能从“便宜”转向“可靠”，靠不丢任务、不重复扣费，再加上草稿档的打样工作流。第四个风险是**受众偏小且会被追赶**：持有 API 密钥的用户本来就少，国内大众靠会员和 cookie 工具，PowerTokens 这类厂商工具和聚合平台随时可能自己做批量界面。第五个风险是**审核与合规**：含真人面孔的素材会被 Seedance 和 Omni 限制；中国的标识办法要求不得去除标识；欧盟 AI 法案第 50 条已于 2026-08-02 生效，存量系统的机器可读标记宽限到 2026-12-02 ([Jones Day](https://www.jonesday.com/en/insights/2026/06/european-commission-publishes-final-code-of-practice-on-marking-and-labelling-aigenerated-content))；LTX-2.5 的许可还要求输出标注为机器生成。工具应当保留供应商写入的元数据，不做二次转码剥离，再提供可选的可见标识和 manifest，这同时也满足了短剧备案“生产过程留痕”的需要。最后一个风险是**证据质量**：本报告的多数事实未能在一手页面上核实，下表列出动工前必须复核的项目。

## 结论

Sora 停用的教训不在于“该换哪个模型”，而在于**模型是易腐品，任务清单才是资产**。第一梯队的几个模型在不同榜单上的分差基本落在置信区间内，价格和促销按月变动，各家下线公告接连不断。在这种市场里，能长期留在用户手上的价值，是一个能把同一份任务清单改投到当下最便宜、最可用模型的队列。这个队列还要保证不丢单、不重复扣费，并在链接过期前把文件取回本地。Sora2App 原先最大的结构缺陷是没有持久化任务库。以前 OpenAI 在服务端替它排了 24 小时的队，这个缺陷还能容忍；现在排队的地方搬到了用户本机，**持久化队列就成了产品本身**。

另一个容易被忽略的推论是，这次改造很可能会让应用的重心向中文用户和国内供应商倾斜。海外用户若想以 Sora 批量价（720p 约 $0.05/秒、带音频）用上 Google 级别的模型，不需要 OAuth 的路线基本只剩 OpenRouter 上的 Veo 3.1 Lite；更便宜的 LTX-2.3 Fast（$0.03/秒）画质明显落后。Veo 3.1 Lite 在 10-22 之后能否继续通过 OpenRouter 供应，是整份推荐里最值得最先查证的一件事。国内的情况是：除了 Vidu 错峰档和低分辨率档，720p 目录价都高于 Sora 批量价（约 ¥0.36/秒），但 MiniMax H3（¥0.50）、Wan 3.0（¥0.6）和可灵 3.0 无声档（¥0.6）仍低于 Sora 标准价（约 ¥0.71/秒），而且批量需求最大的群体（短剧和漫剧工作室）本来就在国内。维护者是中文开发者，界面已经支持中文，再加上国内的标识和备案规则正好需要一个“不剥离、可留痕”的执行层，这些条件凑在一起，说明百炼和火山方舟适配器的战略价值可能不低于海外路线。
